Supervised Learning, Word Embeddings & LLMs

Supervised Learning

This page picks up where Day 1 left off (clean_text_data, etc.) — datasets can be downloaded from the Data Preparation section there.

In supervised learning we have labeled data — we want to learn a model that predicts a target feature. For example, given a biography summary, predict whether it’s of a female or male award winner: the gender column is our target feature, and the text is our predictor.

To build a model that generalizes well, we split data into training and test sets. The training set trains the model; the test set checks how well it does on unseen data. One pitfall: with an imbalanced data set, make sure the target feature’s distribution is similar across both sets (see Model evaluation below).

library(qs)
library(quanteda)
library(quanteda.textmodels)

clean_text_data <- qread("../data/wikipedia_nobel_biographies_summaries_extended_clean.qs")

clean_text_data <- clean_text_data %>%
  filter(pageid != 7152417)

set.seed(123)
clean_text_data$train <- sample(x = c(TRUE, FALSE),
                                 size = nrow(clean_text_data),
                                 replace = TRUE,
                                 prob = c(.8, .2))

corpus <- corpus(clean_text_data, text_field = "extract", docnames = "pageid")

dfm <- corpus %>%
  tokens() %>%
  dfm() %>%
  dfm_remove(stopwords("en"))

dfm_train <- dfm_subset(dfm, train)
dfm_test  <- dfm_subset(dfm, !train)

dim(dfm_train)  # 808 documents, 8239 tokens
dim(dfm_test)   # 200 documents, 8239 tokens

Dictionaries

Dictionaries are a classic tool in text analysis: a predefined list of words associated with specific categories or sentiments. Each dictionary word is assigned to one or more categories, allowing classification of text based on the presence of these words.

set.seed(123)

clean_text_data$train <- sample(c(TRUE, FALSE),
                                 size = nrow(clean_text_data),
                                 replace = TRUE,
                                 prob = c(.8, .2))

corp <- corpus(clean_text_data, text_field = "extract", docnames = "pageid")
toks <- tokens(corp, remove_punct = TRUE) %>% tokens_tolower()
dfm_all <- dfm(toks)

# which words could we add?
dict_gender <- dictionary(list(
  female = c("she", "her", "hers", "herself"),
  male   = c("he", "him", "his", "himself")
))

dfm_pron_all   <- dfm_lookup(dfm_all, dict_gender)
dfm_pron_train <- dfm_subset(dfm_pron_all, train)
dfm_pron_test  <- dfm_subset(dfm_pron_all, !train)

pred_test <- ifelse(dfm_pron_test[, "female"] >  dfm_pron_test[, "male"], "female",
              ifelse(dfm_pron_test[, "female"] <  dfm_pron_test[, "male"], "male", NA))
pred_test <- factor(pred_test, levels = c("female", "male"))

y_test <- factor(docvars(dfm_pron_test, "gender"), levels = levels(pred_test))

caret::confusionMatrix(pred_test, y_test)

Naive Bayes Classification

Naive Bayes (NB) is a simple yet effective probabilistic classifier based on Bayes’ Theorem. It predicts the most likely class by comparing the probabilities of each class given the observed features. The “naive” assumption is that features are conditionally independent given the class, which simplifies computation. NB is widely used in high-dimensional tasks like text classification.

In plain terms: given some conditions, it answers “which outcome is most probable?” For example, given that the weather is rainy and the temperature is 6°C, Naive Bayes can estimate the probability someone will (or won’t) play golf, and classify accordingly.

y <- factor(docvars(dfm_train, "gender"))
nb_train <- textmodel_nb(x = dfm_train, y = y, prior = "docfreq")

class_test <- predict(nb_train, newdata = dfm_test, type = "class")
docvars(dfm_test, "pred_nb") <- class_test

confusion_test <- table(
  predicted = docvars(dfm_test, "pred_nb"),
  truth     = docvars(dfm_test, "gender")
)
confusion_test

The model mostly predicts “male” when the winner actually was male — unsurprising, since male award winners are highly over-represented in the data. Predicting “male” is always a good guess when the target is this skewed — a class imbalance, a well-known ML problem. There are several techniques to tackle it, such as upsampling the minority class.

Model evaluation

A model can make two kinds of mistakes: falsely classifying instances as female when they were male (false positives), and classifying instances as male when they were actually female (false negatives). We have several indicators to assess model performance:

\[Accuracy = \frac{\text{Correctly Classified}}{\text{Total Classifications}}\]

\[Precision = \frac{\text{True Positives}}{\text{False Positives} + \text{True Positives}}\]

\[Recall = \frac{\text{True Positives}}{\text{False Negatives} + \text{True Positives}}\]

Recall is also called Sensitivity or the True Positive Rate.

\[F_1 = 2 \times \frac{Precision \times Recall}{Precision + Recall}\]

Word Embeddings

“The meaning of words is defined by the company they keep” (Firth, 1957). We represent meaning using a vector for each word, constructed so that words similar in meaning are also close together in vector space. The goal is a dense vector per word, similar to the vectors of words that appear in similar contexts. These representations are called word embeddings, because we “embed” words into a low-dimensional space (low compared to the vocabulary size).

Word embeddings are pre-trained on large corpora, e.g. Wikipedia. The most common approaches are Word2Vec, the GloVe project, and fastText — all require substantial computational power and data to train.

Windows — if a word’s meaning is defined by the company it keeps, we can define a window size: how many words before and after the target word count as context.

Imagine a model tasked with predicting a masked word — “the ___ chased the ball”, “the ___ is a pet”. It starts by randomly guessing the embedding for the hidden word. During training the model sees the actual word, compares it to its own prediction, and updates its weights via gradient descent to do better next time. To reduce mistakes, it generates vectors that are closer together for words that frequently appear together in its n-dimensional space.

Gradient descent, in short: compute the slope of the loss with respect to each parameter, and move a tiny step downhill.

df <- qs::qread("../data/wikipedia_nobel_biographies_summaries_clean.qs") %>%
  drop_na()
library(data.table)

# path to your embeddings file
path <- "path/to/your/glove_or_dolma_embeddings.txt"

# Read GloVe-style file (no header line, unlike fastText)
emb <- fread(path, header = FALSE, quote = "", encoding = "UTF-8")

# Split into words + vectors
words <- emb[[1]]
glove <- as.matrix(emb[, -1, with = FALSE])
rownames(glove) <- words

# Example: look up vector for "dog"
glove["dog", ]

dim(glove)  # e.g. 1,200,001 terms x 300 dimensions
library(text2vec)

similarities <- function(target_word, n) {
  # Extract embedding of target word
  target_vector <- glove[which(rownames(glove) %in% target_word), ]

  # Calculate cosine similarity between target word and other words
  target_sim <- sim2(glove, matrix(target_vector, nrow = 1))

  # Report nearest neighbours of target word
  names(sort(target_sim[, 1], decreasing = TRUE))[1:n]
}

similarities("woman", n = 7)
similarities("men", n = 7)
library(text2vec)
library(quanteda)

# Construct corpus
corp <- corpus(df, text_field = "extract")

# Create vocab list based on dfm
vocab <- featnames(
  dfm(tokens(corp, remove_punct = TRUE) %>%
        tokens_tolower() %>%
        tokens_remove(stopwords("en")))
)

# Create function that selects the nearest neighbors
nearest_from_summaries <- function(glove, query, top_n = 20, vocab = NULL) {
  rn   <- rownames(glove)
  cand <- if (is.null(vocab)) glove else glove[rn %in% vocab, , drop = FALSE]

  # expand wildcards (case-insensitive) and collect matches
  to_rx <- function(q) paste0("^", gsub("\\*", ".*", tolower(q)), "$")
  matches <- unique(unlist(lapply(query, function(q)
    grep(to_rx(q), rn, ignore.case = TRUE, value = TRUE)
  )))

  q_vec <- colMeans(glove[matches, , drop = FALSE])

  sims <- text2vec::sim2(cand, matrix(q_vec, nrow = 1),
                          method = "cosine", norm = "l2")[, 1]

  sims <- sims[setdiff(names(sims), matches)]
  sort(sims, decreasing = TRUE)[1:top_n]
}
# "female concept" neighbours (woman, women, female*)
nn_female <- nearest_from_summaries(glove,
  query = c("woman*", "women", "female*"),
  top_n = 20, vocab = vocab
)

# "male concept" neighbours (man, men, male*)
nn_male <- nearest_from_summaries(glove,
  query = c("man", "men", "male*"),
  top_n = 20, vocab = vocab
)

nn_female[1:20]
nn_male[1:20]

Visualization

We can also plot word embeddings, reducing their dimensions to two. The closer terms are to one another, the closer they are in meaning.

library(ggplot2)

show_map <- function(words) {
  M <- glove[intersect(words, rownames(glove)), , drop = FALSE]
  Z <- prcomp(M, center = TRUE, scale. = FALSE)$x[, 1:2]

  df <- data.frame(Z, word = rownames(Z))
  ggplot(df, aes(PC1, PC2, label = word)) +
    geom_point() + ggrepel::geom_text_repel(size = 3)
}

show_map(c("einstein", "curie", "planck", "nobel", "physicist", "chemist",
           "literature", "ernaux", "peace", "literatur", "peac", "united"))

Large Language Models (LLMs)

What are Large Language Models?

Large Language Models (LLMs) are advanced AI models designed to understand, generate, and manipulate human language. They’re built using deep learning, particularly neural networks, and trained on vast amounts of text data to learn language’s statistical patterns and structures. A useful distinction: foundation models are pre-trained on a large corpus and can be fine-tuned for specific tasks; LLMs are a subset of foundation models specifically designed for NLP tasks.

Fine-tuning — take a pre-trained model and specialize it for a downstream task, by training on a smaller, task-specific dataset while keeping the pre-trained weights as a starting point. This adapts the model to a task’s specific nuances without training from scratch.

Prompting — instead of fine-tuning, provide specific prompts or instructions to guide the model’s behavior. More flexible and adaptable, without extensive retraining.

Two flavors of prompting:

  • Zero-shot learning — the model gets a task with no prior examples, relying solely on its pre-existing knowledge.
  • Few-shot learning — the model gets a small number of examples or demonstrations to help it understand the task’s context and requirements.

It’s usually best to start with prompting, and only fine-tune if prompting doesn’t work well enough — fine-tuning has high computational and labor costs and needs large amounts of labeled data.

Why are LLMs so powerful?

LLMs capture the complexities and nuances of human language, enabling a wide range of tasks with high accuracy: generating coherent, contextually relevant text, answering questions, translating, summarizing, and conversing. All LLMs are a form of transformer model. Transformers contain an attention mechanism that weighs the importance of different words in a sentence when making predictions — this captures long-range dependencies and context far more effectively than earlier models like RNNs or LSTMs, which is why LLMs are so transformational for the field.

What are feedforward neural networks?

A feedforward neural network is an artificial neural network where connections between nodes don’t form a cycle — information flows in one direction, from the input layer through one or more hidden layers to the output layer. Each node in a layer connects to every node in the next layer, and each connection has a weight determining the strength of that connection.

See also: StatQuest — Feedforward Neural Networks.

Transformer Models

A transformer model contains a stack of encoders and decoders. The encoder processes the input text through multiple layers of self-attention and feedforward networks to build a rich representation of the input. The decoder uses this representation to generate the output text, again through self-attention and feedforward layers. The attention mechanism lets the model focus on different parts of the input when generating each output word, capturing context and relationships effectively. Transformer models learn to understand language through next-word/sentence prediction and masking particular words.

Running Local LLMs with Ollama

Llama is an LLM developed by Meta and, unlike many competitors, is open source. It’s not as large as GPT-3 or GPT-4, but still powerful and usable for a variety of tasks. Ollama is a platform for running and managing LLMs on your local machine, with an easy-to-use interface for developers and researchers who want to leverage LLMs without extensive infrastructure or cloud services.

library(rollama)

# available models you have installed locally
list_models()

# pull_model("mistral:7B")  # download a model

ping_ollama()  # check if the Ollama server is reachable

System and user prompts are core components of prompt engineering. A system prompt gives the model foundational instructions — assigning a role (“You are a research assistant”) and constraints (ethical guidelines, style, behavior). System prompts are typically consistent across sessions. A user prompt contains task-specific instructions (“Classify these sentences into categories”), possibly with extra context or examples.

We’ll try zero-shot learning first: get some text, construct the prompt, and send it to the model.

# We can simply talk to the model
rollama::query("What is the capital of New York", model = "llama3.1")

# Construct the query: a system message assigns a role, then the
# user prompt supplies the task-specific text.
df$zero <- NA_character_

for (i in 1:2) {
  question <- "Task: You're a research assistant that helps to analyze texts. Your aim is to classify whether the summary of a biography describes a female or a male Nobel prize winner."
  text <- df$extract[i]
  question <- paste(question, text)
  result <- query(question, model = "llama3.1")
  print(result)
  df$zero[i] <- result[[1]]$message$content
}

## Visualization

We can also plot word embeddings, reducing their dimensions to two.
The closer terms are to one another, the closer they are in meaning.

```{r}
#| label: embedding-plot
library(ggplot2)

show_map <- function(words) {
  M <- glove[intersect(words, rownames(glove)), , drop = FALSE]
  Z <- prcomp(M, center = TRUE, scale. = FALSE)$x[, 1:2]

  df <- data.frame(Z, word = rownames(Z))
  ggplot(df, aes(PC1, PC2, label = word)) +
    geom_point() + ggrepel::geom_text_repel(size = 3)
}

show_map(c("einstein", "curie", "planck", "nobel", "physicist", "chemist",
           "literature", "ernaux", "peace", "literatur", "peac", "united"))
```

## Large Language Models (LLMs)

### What are Large Language Models?

Large Language Models (LLMs) are advanced AI models designed to
understand, generate, and manipulate human language. They're built
using deep learning, particularly neural networks, and trained on vast
amounts of text data to learn language's statistical patterns and
structures. A useful distinction: **foundation models** are pre-trained
on a large corpus and can be fine-tuned for specific tasks; **LLMs**
are a subset of foundation models specifically designed for NLP tasks.

**Fine-tuning** — take a pre-trained model and specialize it for a
downstream task, by training on a smaller, task-specific dataset while
keeping the pre-trained weights as a starting point. This adapts the
model to a task's specific nuances without training from scratch.

**Prompting** — instead of fine-tuning, provide specific prompts or
instructions to guide the model's behavior. More flexible and
adaptable, without extensive retraining.

Two flavors of prompting:

- **Zero-shot learning** — the model gets a task with no prior
  examples, relying solely on its pre-existing knowledge.
- **Few-shot learning** — the model gets a small number of examples or
  demonstrations to help it understand the task's context and
  requirements.

It's usually best to start with prompting, and only fine-tune if
prompting doesn't work well enough — fine-tuning has high computational
and labor costs and needs large amounts of labeled data.

### Why are LLMs so powerful?

LLMs capture the complexities and nuances of human language, enabling a
wide range of tasks with high accuracy: generating coherent,
contextually relevant text, answering questions, translating,
summarizing, and conversing. All LLMs are a form of **transformer
model**. Transformers contain an *attention mechanism* that weighs the
importance of different words in a sentence when making predictions —
this captures long-range dependencies and context far more effectively
than earlier models like RNNs or LSTMs, which is why LLMs are so
transformational for the field.

**What are feedforward neural networks?**

![Feedforward Neural Network Architecture](../images/feedforward-nn.jpg)

A feedforward neural network is an artificial neural network where
connections between nodes don't form a cycle — information flows in
one direction, from the input layer through one or more hidden layers
to the output layer. Each node in a layer connects to every node in the
next layer, and each connection has a weight determining the strength
of that connection.

See also: [StatQuest — Feedforward Neural Networks](https://www.youtube.com/watch?v=CqOfi41LfDw).

### Transformer Models

![Transformer Model](../images/transformer-model.png)

A transformer model contains a stack of encoders and decoders. The
encoder processes the input text through multiple layers of
self-attention and feedforward networks to build a rich representation
of the input. The decoder uses this representation to generate the
output text, again through self-attention and feedforward layers. The
attention mechanism lets the model focus on different parts of the
input when generating each output word, capturing context and
relationships effectively. Transformer models learn to understand
language through next-word/sentence prediction and masking particular
words.

## Running Local LLMs with Ollama

Llama is an LLM developed by Meta and, unlike many competitors, is open
source. It's not as large as GPT-3 or GPT-4, but still powerful and
usable for a variety of tasks. [Ollama](https://ollama.com/) is a
platform for running and managing LLMs on your local machine, with an
easy-to-use interface for developers and researchers who want to
leverage LLMs without extensive infrastructure or cloud services.

```{r}
#| label: rollama-setup
library(rollama)

# available models you have installed locally
list_models()

```

System and user prompts are core components of prompt engineering. A
**system prompt** gives the model foundational instructions — assigning
a role ("You are a research assistant") and constraints (ethical
guidelines, style, behavior). System prompts are typically consistent
across sessions. A **user prompt** contains task-specific instructions
("Classify these sentences into categories"), possibly with extra
context or examples.

We'll try zero-shot learning first: get some text, construct the
prompt, and send it to the model.

```{r}
#| label: rollama-query
# We can simply talk to the model
rollama::query("What is the capital of New York", model = "llama3.1")

# Construct the query: a system message assigns a role, then the
# user prompt supplies the task-specific text.
df$zero <- NA_character_

for (i in 1:2) {
  question <- "Task: You're a research assistant that helps to analyze texts. Your aim is to classify whether the summary of a biography describes a female or a male Nobel prize winner."
  text <- df$extract[i]
  question <- paste(question, text)
  result <- query(question, model = "llama3.1")
  print(result)
  df$zero[i] <- result[[1]]$message$content
}
```
